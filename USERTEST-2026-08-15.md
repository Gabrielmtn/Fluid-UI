## Wave A — verified surgical fixes (all independent; ~1.5 days total)

### A1. Restore Paint Into / Stroke selection highlights — XS ⭐ fixes 2 reported bugs
- **Root cause:** [12-save-load.js:1067](js/12-save-load.js:1067) — applyPresetSnapshot's replayMode restore queries **all** `.brush-mode-btn` and strips `active` from ~19 buttons that lack `dataset.mode` (only the Replay Stroke/Time pair has it — [20-mixer-layout.js:1746](js/20-mixer-layout.js:1746),1752). Fires on every preset/Scene apply, `.fluid` import, variant jump, and **every Take Turns look-mirror apply (≤ every 400ms)** — including the ⟳ Live collider buttons. Defaults ARE set correctly at build; a single Scene click wipes them.
- **Fix:** scope the query to `.brush-mode-btn[data-mode]`.

### A2. Stop the look-mirror rewriting watchers' sketch/mask prefs — S (rest of the settings-share bug)
- **Root cause:** registry checkboxes `brushEraser` + `sketchVisible` ([01a-param-registry.js:111](js/01a-param-registry.js:111)) ride turn-look snapshots; `setCheck` dispatches `change` → pCheckbox handler ([20-mixer-layout.js:2131](js/20-mixer-layout.js:2131)) writes config **and persists into the watcher's settingsManager** — the painter's eraser/paint-layer state silently overwrites your saved prefs, surviving reload.
- **Fix:** add both to `MP_PERF_LOCAL_KEYS` ([06-multiplayer.js:316](js/06-multiplayer.js:316)); receiver-side skip of these two ids when `__mpApplyingRemote` ([12-save-load.js:889](js/12-save-load.js:889), same pattern as preserveFluidOpacity); optional hardening: skip the settingsManager persist entirely during remote apply. Side effect (desired): host settings-lock stops mirroring them too. No wire-format change; old clients handled by the receiver skip.
- **Note:** `BRUSH_TARGET` itself verifiably cannot ride the share — its only writer is setBrushTarget. A1+A2 together account for the observed symptom.

### A3. Brush size label lag — XS
- **Root cause:** label binds to slider `input`/`change` + a 2s interval fallback ([20-mixer-layout.js:113](js/20-mixer-layout.js:113)). Mobile pinch-resize ([05d-input-replay.js:708](js/05d-input-replay.js:708)) and desktop wheel-resize ([05h-slider-bindings.js:473](js/05h-slider-bindings.js:473)) write `slider.value` directly, never dispatch — label snaps up to 2s later.
- **Fix:** dispatch `new Event('input', {bubbles:true})` in both paths (exact precedent: preset apply, [20-mixer-layout.js:2205](js/20-mixer-layout.js:2205)). Fan-out audited safe; MP mirror is 400ms-debounced. **Keep the 2s interval** — the COS oscillator writes per-frame without events.

### A4. Multi-brush swatch shows the real color — XS
- **Root cause:** the row swatch is always `cfg.color` ([20-mixer-layout.js:4144](js/20-mixer-layout.js:4144)); a "main"-mode arm (leftmost option, follows default color) actually paints `pointer.color` — so the swatch shows a stale custom hex and never tracks the default.
- **Fix:** display-only — when `cfg.mode==='main'`, set `picker.value` from the live default color. **Never** write it into `cfg.color` or dispatch input on the row picker (its handler flips the arm to `fixed` and persists). Live tracking while open comes free via the existing rebuild.

### A5. Three-colors flash on mouseup — S
- **Root cause:** color advance is decoupled from actual paint end. `BrushEngine.end()` leaves stabilizer catch-up dabs queued (drain ≤64/frame over later frames), but `advanceArmColors()` runs immediately: synchronously in instant mode ([05d-input-replay.js:551](js/05d-input-replay.js:551)), or when the splat-out tail dies while ignoring `BrushEngine.pending()` ([05j-update-loop.js:275](js/05j-update-loop.js:275)). Late dabs then paint arms>0 with NEW rerolled colors while arm 0 keeps the OLD pointer color. Touch twin at 05d:839.
- **Fix:** always defer via `pendingArmAdvance`; flush only on full paint idle: `!splatOutActive && !BrushEngine.isActive() && !BrushEngine.pending()` — colocated with the existing full-idle gate at [05j-update-loop.js:264](js/05j-update-loop.js:264). `pendingArmAdvance` must stay declared in 05d (classic-script shared lexical global).
- **Caveat:** shifts Math.random draw order — bit-identity A/B harness runs will legitimately diverge.

### A6. Record can't kick you out of turns — S
- **Root cause:** it's not the record function — it's the "⏺ Multi" buttons sitting beside "⏺ Record" ([index.html:950](index.html:950), 1020) with the identical record glyph. They're a raw multiplayer connection toggle ([03-recording.js:1055](js/03-recording.js:1055)): one click → `disconnectMultiplayer()` no confirm → relay removes you from turnQueue and passes the brush ([party/index.ts:474](party/index.ts:474)). Unrecoverable: `lastRoom` is never set on this path so Reconnect never appears, and clicking again mints a brand-new empty room.
- **Fix:** confirm-guard the disconnect branch in `recToggleMultiplayerActivation` (one function covers both buttons); relabel/re-icon both to 🌐 so they stop reading as record buttons (label-only; keep ids + `.action-multi`); set `lastRoom` before clearing so a misclick still offers Reconnect for private rooms. **No relay change, no partykit redeploy.**

### A7. Custom-brush giant square — S
- **Root cause:** authored into the stamp at import, not a GL bug. The mask editor's ✓ Apply button ([15-layer-masking.js:347](js/15-layer-masking.js:347)) is never disabled; Magic Mask is a slow CPU async chain (model download → embed → 200ms debounce → inference). Apply before the green preview lands → no-mask fallback → `1 - luminance` over the whole image → near-solid full-file-rect stamp; processStamp crops to the whole file; the splat shader faithfully prints the rectangle. Also reachable with zero Magic Mask points on a dark opaque image (that's the *designed* silhouette-import fallback — keep it). Ruled out: texture races, NPOT wrap, the multiplayer shape-id gap.
- **Fix (all in 15-layer-masking.js + one line in 05m):** block Apply while SAM is busy/pending points with a "still cutting out your object" message; disable `.mask-apply-btn` during processing; same guard for the image-layer twin (15:1928); skip empty sam-mask shapes instead of filling their bounding rect ([05m-layer-masks.js:281](js/05m-layer-masks.js:281)).
- **Note:** already-authored broken stamps persist in `brush.shapes` libraries — users delete by hand; don't auto-purge.

### A8. Remote/replay strokes stamped with YOUR brush shape — S *(new bug found while verifying A7)*
- **Root cause:** remote dabs ([06-multiplayer.js:1607](js/06-multiplayer.js:1607)) and timeline replay ([05d-input-replay.js:309](js/05d-input-replay.js:309)) omit `exactColor` → `__brushTipOn=true` → `splat()` uses the LOCAL viewer's `BrushShapes.getActiveStamp()`. Built-in tips doing this is intentional design; the custom stamp riding the same gate is not (its bitmap can't travel). Worse: every look-mirror apply nulls the watcher's own shapeId **and persists the null** ([12-save-load.js:1467](js/12-save-load.js:1467)) — your shape selection is lost across reloads.
- **Fix (containment now):** gate only `getActiveStamp()` behind a "local stroke" flag around the remote/replay call sites (built-in tips keep working for peers); remember and restore the watcher's shapeId around the look-lock. Real fix (stamp bitmap on the wire) stays the existing roadmap item.

### A9. Sliders draggable with touch/stylus — S (CSS-only)
- **Root cause:** native `input[type=range]` with **no `touch-action` anywhere** on the fader family, inside scrollable ancestors — the browser claims the drag as a pan, fires pointercancel, only taps commit. The repo already fixed this exact failure once ([styles.css:1402](css/styles.css:1402), `.layer-threshold`). The row-drag forwarder deliberately excludes touch and skips presses on the input itself, so it can't save pens either.
- **Fix:** `touch-action: pan-y` on the base range rule ([slider-styles.css](css/slider-styles.css)) + `.control-group` + `.ch-fader` (forwarding never applies to strip channels — they need the rule directly); bump coarse-pointer thumb to ~28px. **pan-y, not none** — none would kill drawer swipe-scroll. On-device check: drawer still scrolls (iOS), strip still pannable from labels/gaps.

## Wave D — mobile zoom

### D1. Kill accidental page zoom — S (safe, ship with Wave A)
Verified: viewport meta already forbids scaling but **iOS ignores it**; `touch-action:none` protects only the canvas — pinch/double-tap on the drawer/buttons zooms the page and it's fiddly to get back. Fix: `touch-action: manipulation` on body/strip/sidebar/buttons + non-passive `gesturestart`/`gesturechange` preventDefault + multi-touch guard outside `#canvas` (in 13-mobile-mode.js).

### D2. Make intentional zoom exist on touch — M  🔶 decision needed
There is currently **no touch path that zooms the canvas at all** (ZoomView is wheel/hotkey-Z only) — and two-finger pinch on the canvas is bound to **brush size** ([05d-input-replay.js:703](js/05d-input-replay.js:703)), so users expecting pinch-zoom get a brush resize: "zoom is broken." Proposal: rebind canvas pinch → `ZoomView.zoomAt` (transform + input mapping already work while zoomed; clamp 1..12; mandala Fill shares the transform) and let brush size live on the now-draggable fader (A9). This rebinds a shipped gesture — your sign-off.
