## E. Audio rebuild (after the fest)

The direction you named: **build audio around the timing tool.** Detected events become small, bindable actions you can delete and nudge one by one, saved as a timing file per track for playing along.

- **Why Full feels wrong today:** the composer runs its own 16 s clock, never reads the track's position and draws no waveform, so blocks can't line up against the song. Segments only store engine config (no gates, no scene options). The composer sits below the fold of a 38vh drawer. Sliders are huge because the drawer isn't in the sidebar: it gets the base 44px fader and the min/mid/max scale row, then the ui-scale zoom. The header claims adaptive peak tracking, which doesn't exist.
- **Plan shape:** the timing chart as the hub; per-track `cues` file; event → action bindings (pulse brush, colour step, kaleido step, splat at…); a nudge/delete editor on the chart; the composer either rides the track clock or goes.
- **Your pattern-matcher idea fits the existing cache:** js/40 already keeps a 256-column log spectrogram per track. Drawing a box over a time×frequency "shape" and finding its repeats (normalized cross-correlation) is a direct extension. The ✨Auto + Fit band finder becomes the low/mid/high wizard.
- **BPM:** offline BPM exists for files (beat lanes). Use it for "every N beats" first; a live tempo tracker for mic/system audio later.
- Library choice: see Questions.

## Questions you asked

**Is replay speed accurate?** Mostly, with known edges.
- **Right-click replay:** runs on the wall clock and is accurate at 10 fps and up. It ignores the Time fader, so it only matches the original stroke when Time and fps match the moment it was painted.
- **Recorder:** recorded on the wall clock but played on the sim clock. At 60 Hz that was about 4% slow (a 10 s take ran ~10.4 s), more under load, and twice as long at Time 0.5. ✅ **52a0187:** a take is stamped on the clock it plays on. Headless at Time 0.5: a 3.0 s take played back in 6.0 s before, 3.0 s now.
- **Right-click replay after a resize** landed in the wrong place; ✅ **c635897** (see B).

**Can the demo detect a wishlist?** Not reliably. Steamworks has no "is this wishlisted" call for a game.
- Steam's web API has an `IWishlistService`, but community tools report that it only returns wishlists their owners made public.
- **Dependable route:** remember the click on "Wishlist on Steam" and ask less after it.
- **Optional extra:** a best-effort check on public wishlists when the window regains focus.

**Is there an audio library to build on?** The licence decides, because the game is closed source.
- **Essentia.js:** does everything (onsets, beat tracking, BPM) but is AGPL-3.0, so it's out unless you buy their commercial licence.
- **aubio:** GPL, so it's out for the same reason.
- **Meyda (MIT):** feature extraction. Raw material for the pattern matcher.
- **realtime-bpm-analyzer (Apache-2.0) and web-audio-beat-detector (MIT):** BPM.
- **Spotify's basic-pitch (Apache-2.0, ONNX):** could run on the transformers.js runtime you already ship.

js/40 already has superflux onsets, a beat lane with BPM and a pitch lane. The gap is the workflow (E), not the maths, so pick a library after the timing-tool rework shows what's missing.

**Apple dev account.** The $99 account is what lets a Mac build be signed and notarized, for a Steam Mac depot or the Mac App Store.
- The 09-26 plan still stands: Mac after the Nov 2 launch, built on a free macOS GitHub runner.
- The more interesting Apple store is the iPad with Pencil. That's a separate wrapper project, not an Electron build.
