## Conventions for this list

- **Owner sheet.** Put these rules in a new sheet, `css/41-theme-drawer-content.css`, linked in `index.html` right after line 261 (`40-theme-overlays.css`), in `@layer theme`.
  - js/38's button-audit regex `(3[13-9]|4\d)-theme-[a-z-]+\.css` (`js/38-button-audit.js:27`) already lets it colour buttons, so a button tint (`.danger`) is legal there.
  - Rules that belong to an existing component go to that component's sheet:
    - tubes and head rows: `css/36`
    - fields and checkbox panes: `css/37`
    - floating lists and the colour picker: `css/40`
  - The owner column below names one of 41, 36, 37 or 40. If the integrator prefers fewer sheets, 41 can fold into 35 after W1 has merged.
- **Selectors.** Prefix every selector with `html[data-theme="walnut-copper"]`. An inline `style=""` needs `!important` (rows say so).
- **Study recipe names are names only. Never add study classes to the DOM.**
  - The colour picker's root is already `div.cp` (`js/64-colour-picker.js:197`, 49 rules in `css/23-colour-picker.css`).
  - A literal port of `.cp{...}` would repaint the picker as a pane. Write each recipe under the app's own hooks.
- **Hooks.** Every hook named below is an existing class or id from the live DOM. `prep/selector-contract.md` lists them as JS-written (`write`) or JS-read (`both`). Style through them; do not rename or repurpose any. The `both` ones are queried by script: `.layer-btn` (`js/13-drag-scroll.js:19`, `js/44`), `.layer-check`, `.layer-slider-value`, `.drop-zone`, `.palette-select-trigger`, `.palette-chip`, `.palette-list`, `.palette-option`, `.mutation-card`, `.hk-cap`.
- **Tests that touch these drawers:** `scripts/test/palette-picker/run.js`, `palette-extract/ui.js`, `dialog-focus/run.js` and `pointer-only/run.js`. Size changes must leave them passing. If a test hard-codes a coordinate, fix the test by measuring right before use (HANDOFF rule).

## Questions for Gabriel and risks for the second wave

1. **The pane tier (C1) is global.** Moving every sidebar pane from 36 px wrapping to 32 px `nowrap` is the study's rule, but it changes every drawer at once. It needs the fit rows (L1, L22, L25, L26, K8, M3, plus the other gap specs' equivalents) in the same change, or labels will clip.
2. **Layer rows can't be collapsed from the keyboard.** The header is the only control (05k:626) and it is not focusable; the caret is `aria-hidden`. The study's `.disc` is a real button with `aria-expanded` and `aria-controls`. Adding it is a small change in 05k (a new focusable element in the study's own pattern). Ask before doing it; it is outside a presentation-only pass.
3. **Scope Basic / All expose no state.** Only the `.active` class marks it, and the real `<select id="mutationScope">` is `aria-hidden` with `tabindex=-1`. Adding `aria-pressed` in js/20:2947 is a one-line a11y improvement. Ask.
4. **Variant cards are mouse-only.** Only the "N changes" span is focusable. The study's tile pattern (`.st` in a radiogroup, arrow keys) would change behaviour. Information only.
5. **`label.collision-label` has no `for` (05k:118).** Clicking "Invert" or "Mode" text does nothing. Don't style those rows as one big pane (L16). Adding `for` is JS: ask.
6. **Field tier inside layers (L17).** The study uses 32 px `.cp.sel.sm` for Clip and Collision mode; W3's brief says 48 px for sidebar fields. Pick one.
7. **Lamp, not checkbox, for layer visibility (L11).** This overrides whatever W3 does to `.layer-vis` in the merge. Say so to the integrator.
8. **Re-rendered DOM.** js/01 rebuilds `#paletteSelect`, `renderLayers()` rebuilds `#layersPanel`, js/24 rebuilds `#pathLayersList`, and js/20 rebuilds `#mutationGrid`. Any `ThemeMotion.pane` registration needs a childList `MutationObserver` on those hosts from a theme script, never a per-frame scan. Resting states must be pure CSS (`:has(:checked)`, `.active`, `[aria-selected]`), because presets and sync change state without events.
9. **Forced colours.** Each new recipe needs the study's forced-colors lines:
   - (322-326): `border:1px solid ButtonText` on panes, tubes, screens and swatches; `outline:3px solid Highlight` on checked or pressed panes.
   - (399): lamps, text fields, CRT and gates; `.lamp[aria-checked=true]` → `Highlight`.
10. **No layout reads, no loops.** Every row above is static CSS, grid or flex placement, or a pseudo-element. The only motion candidates are L7 (needs W1's technique or a perf trace) and the existing `ThemeMotion.pane` strikes.
11. **Shots taken before the W merges.** Re-shoot after the merge with `prep/work/gaps/scripts/states.js` and `states2.js` (`W=1920 VH=2600` / `W=1440 VH=2400`, `NODE_PATH` set to the main checkout's `node_modules`), and drop rows the merge has already fixed.
