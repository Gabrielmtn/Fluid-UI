# F — Baselines (seven scripted captures)

Read `prep/briefs/_preamble.md` first. Each sub-task below is its own agent. Every capture is a script under `prep/baseline/scripts/` that (a) captures and (b) checks against a saved baseline (`--check` mode, exit 1 on mismatch), because the later CSS steps are gated by re-running them. Record environment facts in every output (Chrome version from `/json/version`, viewport, DPR, `--ui-scale`, date, HEAD commit). Use the repo driver (`scripts/test/radial-menu/driver.js`), the harness (`scripts/test/harness.js`, `stage.js`) and `scripts/test/cdp.js`; read `scripts/test/README.md`. One Chrome per agent, closed in `finally`. Write your capture's notes (what it does, how to run capture and `--check`, caveats, nondeterminism found and how it was pinned, the `--check` result you observed) to `prep/baseline/<area>/NOTES.md`; F7 assembles `prep/baseline/README.md` from those.

## F0 — DOM dump (`prep/scripts/dom-dump.js`) — runs first; A and F3/F4 consume it

Boot, wait for the splash to go, hide `#photoWarn`, open the left sidebar if folded, open every right-sidebar section (Shift-click each `.section-title` so the accordion keeps them open; verify `aria-expanded="true"` on all), then enumerate every interactive element: `button, input, select, textarea, a[href], [role], [tabindex], [contenteditable], summary, label` plus `.section-title`, `.mixer-channel`, `.sidebar-section`. For each record: `surface` (`mixer-strip` / `sidebar-left` / `sidebar-right` / `canvas-area` / `titlebar` / `overlay:<id>` / `body`), `section` (nearest `.sidebar-section` title or `.mixer-channel` label), `order` (document order index), `tag`, `type`, `id`, `classes`, `role` and `name` from CDP `Accessibility.getFullAXTree` (map by `backendDOMNodeId` via `DOM.getDocument` + `DOM.querySelectorAll`; fall back to a page-side name computation when the node is ignored), `aria` (all `aria-*`), `dataAttrs`, `value/min/max/step/checked/disabled`, `tabIndex`, `labelFor`/`labelledBy` text, `title`, `visibleAtBoot` (before expanding), `rect`, `parentChain` (ids/classes to the surface root). Also list sections (`title`, `data-group`, collapsed at boot, DOM order) and overlays present in the DOM at boot (`#hotkeyOverlay`, modals, toasts). Write `prep/baseline/dom/controls.json` and a human `prep/baseline/dom/controls.md` (counts per surface and per role; the full list as a compact table). Then open and dump the lazily-created UI too: radial menu (`e` key), colour picker popover (click the colour well), presets popup, arm-tip menu, each into `prep/baseline/dom/lazy-<name>.json`; close each with Escape.

## F1 — Screenshots (`prep/baseline/scripts/screenshots.js`)

Widths 1366, 1440, 1920, 2560 (heights 768, 900, 1080, 1440) via `Emulation.setDeviceMetricsOverride` (DPR 1), reload after each so `--ui-scale` recomputes; record the scale. Deterministic canvas: inject `harness.js`, `await __test.freeze()`, `__test.clear()` (or `clearCanvas()`), wait for `.ui-enter` entrance animations and the splash to end (poll `getAnimations().length === 0` on the strip, plus a 600 ms settle); the nav idle glow and breathing run on rAF and stop under the freeze. Shots per width: full page; top bar crop (`#mixer-strip` rect); left sidebar open; each right-sidebar section open alone (14) with the sidebar scrolled so the section is in view; key states on a representative control each: pressed (`aria-pressed` button, e.g. a toggle in the strip), checked (a checkbox), expanded (a section), focused (`focus()` a fader then `:focus-visible` via `Emulation.setFocusEmulationEnabled` + keyboard Tab), disabled (find a `:disabled` or `aria-disabled` control; if none exists, say so). Also the F1 overlay, the radial menu, the colour picker popover, the presets popup. Name files `<width>/<shot>.png`. Save a `manifest.json` (shot → selector/state/rect/scale). `--check` mode re-captures to a temp dir and compares with `sharp` (raw pixel buffers; report mismatched pixel count and write a diff PNG per mismatch under `prep/baseline/screenshots/_diff/`); exit 1 on any mismatch. Run `--check` once against the fresh baseline and record the result (it must be zero; if it is not, find the nondeterminism, fix the capture, and document it).

## F2 — Frame time and layout (`prep/baseline/scripts/perf-trace.js`) — run alone, no other Chrome open

Boot at 1440×900 (note headless GPU: record `gl.getParameter(gl.RENDERER)` / `UNMASKED_RENDERER_WEBGL`). Use CDP `Tracing.start` with categories `devtools.timeline,disabled-by-default-devtools.timeline,disabled-by-default-devtools.timeline.frame,blink.user_timing,v8.execute` and `Tracing.end` → collect `Tracing.dataCollected`. Three phases of 20 s each (60 s total): idle with the sim running (paint one stroke first via `Input.dispatchMouseEvent` so there is dye), dragging a top-bar fader continuously (trusted mouse moves across the `#curl` channel's proxy or the canonical input's rect, ~60 moves/s), idle again. From the trace compute per phase: frame intervals (from `DrawFrame`/`BeginMainThreadFrame` or `Commit` events) median and p95, long tasks (`RunTask` > 50 ms), count of `Layout`, `UpdateLayoutTree` (style recalc), `Paint`, `CompositeLayers` per frame, and forced synchronous layouts (`Layout` events nested inside `FunctionCall`/`EventDispatch`, or `ForcedLayout`/`InvalidateLayout` with stack). Also sample `window.__stats` if present. Run the whole capture three times; write `prep/baseline/perf/run-<n>.json` (summary) and `trace-<n>.json.gz`, plus `prep/baseline/perf/summary.md` with the three runs side by side and the run-to-run noise (max−min per metric). `--check` re-runs once and flags any metric worse than baseline mean + noise. State clearly that headless numbers are relative, not the user's machine.

## F3 — Accessibility (`prep/baseline/scripts/a11y.js`)

Vendor axe-core: `npm pack axe-core` into `prep/baseline/vendor/` (then extract `axe.min.js` and `LICENSE` from the tarball; delete the tarball; do NOT `npm install`). Boot, open everything as F0 does, inject axe, run `axe.run(document, { resultTypes: ['violations','incomplete'] })` with the default WCAG tags; also run with each overlay/popover open (F1 overlay, radial menu, colour picker, presets). Write `prep/baseline/a11y/axe.json` and `axe.md` (violations grouped by rule, with selectors). Then the hand-written list: from `prep/baseline/dom/controls.json` derive `prep/baseline/a11y/controls-a11y.md` — one row per control: selector, role, name, state attrs, keyboard pattern (native for input/button/select; custom where `role=` is set — read the handler to say which keys), and a `--check` mode that recomputes role/name/state from a fresh boot and diffs against the saved list (exit 1 on any change). Run `--check` once.

## F4 — Keyboard order (`prep/baseline/scripts/tab-order.js`)

Boot, open everything as F0 does, click the canvas once to settle focus, then press Tab (trusted, via the driver's `tap`) up to 800 times recording `document.activeElement` (selector, role, name, surface) until the sequence returns to its first stop; then Shift+Tab the same way for the reverse order. Also record what the skip menu does on first Tab (js/66). Write `prep/baseline/keyboard/tab-order.json` and `.md`. `--check` re-runs and diffs the sequence (exit 1 on difference). Note the existing suites that cover keyboard behaviour (`scripts/test/{focus-keys,skip-menu,bar-keys,dialog-focus,slider-keys,popup-focus}/run.js`).

## F5 — Sync log (`prep/baseline/scripts/sync-log.js`)

Start a local relay: try `npx wrangler dev --port 8787 --ip 127.0.0.1` (log to a temp file, wait for "Ready"); if it fails, try `npx partykit dev` on 1999. Boot two headless Chromes through the driver with `seed: { fluidMultiplayerHost: '127.0.0.1:<port>' }` (the key the app reads, `js/06a-mp-core.js:69`). On A: `createRoom()`; wait for `currentRoom && partySocket.readyState === 1`; on B join that code (`joinRoom(code)` or whatever 06a exposes; read it), wait for `connectedClients >= 2` on both. On B, before the sequence, wrap the socket: `partySocket.addEventListener('message', e => window.__syncLog.push(...))` storing `{ t: performance.now() - t0, type, keys, payload }` with volatile fields normalised (timestamps → 0, uids/room code → tokens, floats rounded to 6 dp). Then run a fixed sequence on A, one action per 250 ms, each by dispatching `input`+`change` on the real element: a shared slider (`#curl` 10→40 in 4 steps), a shared checkbox toggle, a shared select, a palette change, a preset apply, the brush size (`#brushSize`, personal: must NOT arrive), a brush-section control (personal), gravity pad write, a Clear. Wait 3 s, pull `__syncLog` from B, and also log what A sent if the code exposes a send hook (otherwise wrap `partySocket.send`). Write `prep/baseline/sync/log.json`, `log.md` (table: step → messages B received, with the personal controls confirmed absent), and `relay.md` (how the relay was started). `--check` re-runs and diffs the normalised log (exit 1 on difference). Kill the relay and both Chromes in `finally`.

## F6 — Bundle, suites and button audit (`prep/baseline/scripts/bundle.js`)

Sizes: each `css/*.css`, `index.html`, each `js/*.js` (non-vendor) with a total, `assets/` by type, fonts bundled today (none expected; confirm), `js/vendor/` size; write `prep/baseline/bundle/sizes.json` + `.md`. Then run the existing UI suites once each (`node scripts/test/<suite>/run.js` for radial-menu, focus-keys, skip-menu, bar-keys, dialog-focus, slider-keys, popup-focus, stroke-lock, pen-window; the look-links suite without `MP_HOST`), sequentially, capturing exit code and PASS/FAIL lines into `prep/baseline/suites/<suite>.log` and a summary `suites.md`. Finally boot once and record `window.auditButtons()` output to `prep/baseline/bundle/button-audit.json` + `.md` (this is the existing style-contract gate). `--check` for this one = re-run suites and the button audit and compare pass counts.
