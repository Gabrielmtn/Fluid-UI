## Frozen (do not change)

- **Behaviour:** what any control does, its value, range, step, default, keyboard handling, event order, timing, persistence.
- **Sync:** what goes over the network, message shapes, throttling, merge rules.
- **Selectors script depends on:** every id, class and data attribute that JavaScript queries or toggles keeps its name and meaning (`prep/selector-contract.md`). Add styling hooks beside them, never in place of them.
- **Accessibility only goes up.** Roles, names, states, focus order and live regions stay at least as good. A new focusable element is allowed only when it is the study's pattern and fully keyboard operable; list it in your report.
- **Performance.** No new animation loops (`requestAnimationFrame`, `setInterval` animation, or CSS animation that runs forever while idle). No layout reads in the frame (`getBoundingClientRect`, `offsetWidth` and friends). No layout change after boot: sizes are fixed in CSS, never measured late and snapped. All motion rides js/71's single frame through `window.ThemeMotion` (below).

## How the theme is built

- Every theme rule is in `@layer theme` and scoped to `html[data-theme="walnut-copper"]`. The layer order is declared in `css/00-tokens.css`.
- An inline `style=""` beats every layer. Where script writes inline styles, the theme needs `!important`.
- **Never register or write `--i`.** The app writes an inherited `--i` on every sidebar section (js/20 `stampGroupRows`). The theme's cathode brightness is `--ci` (registered number, 0 to 1).
- Button colour may live only in `css/01-buttons.css`, `css/31-theme-components.css` and `css/33`–`39` theme sheets, or the button audit (js/38) fails.
- The top bar's material select keeps the system font: js/29 sizes it by measuring its text.
- `css/32-theme-remap.css` is generated by `scripts/theme/gen-remap.js`. Don't edit it by hand.
- Tokens: `--cu #c47a4b`, `--cu-hi #f2b38a`, `--cu-lo #5a2e17`, `--engrave #e7d2b2`, `--lit #ffd9b0`, `--unlit #a08a76`, `--vfd #72f2d4`, `--mesh-dim`, fonts `--ui-font-display` (Michroma), `--ui-font-mono` (Share Tech Mono), `--ui-font-body` (Libre Franklin). See `css/30-theme-walnut-copper.css`.

## Motion: `window.ThemeMotion` (js/71)

js/71 is a port of the study's motion: `Spring` with profiles local (k 600, z 0.70), drawer (180, 0.85) and remote (120, 0.95); `Cathode` (on 45 ms local / 220 ms remote, off 300 / 450 ms, 170 ms strike flicker on a local turn-on); the press surge; drawer `--dp`; the tray rosette `--rot`; range springs `--sp` / `--spp`; remote tints `--ga` / `--pc` / `--tgc` and name chips. js/05j calls `window.__themeFrame()` once per drawn frame; it returns at once when nothing moves. Hooks for your script:

| Call | What it does |
|---|---|
| `ThemeMotion.run(fn)` | Steps `fn(dt, T)` every frame until it returns true. Call again to re-wake. |
| `ThemeMotion.pane(el, isOnFn?, opts?)` | Makes `el` a cathode pane: `--ci` follows its state with the study's timing, plus the press surge. Without `isOnFn` the state is the checked state of the checkbox or radio that `el` is or holds, and `--ci` is written only while moving, so give the resting state a CSS rule (for example `:has(input:checked)`). |
| `ThemeMotion.sync(el)` | Re-reads a pane's state after a change no attribute shows. |
| `ThemeMotion.kick(el)` | Spins the rosette of `el`'s drawer. |
| `ThemeMotion.Spring`, `.Cathode`, `.PROF`, `.reduced()`, `.now()` | The primitives, for your own steppers. |

Buttons, `.btn` and `.wc-opt` are panes automatically (lit by `aria-pressed`, `aria-checked`, `aria-selected`, `.active`, `.locked`). Under reduced motion, springs jump to target and cathodes switch with no flicker.
